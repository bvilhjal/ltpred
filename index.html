ltpred

Liability-threshold genetics at pedigree and registry scale.

A from-scratch Python implementation of LT-FH++, ADuLT and PA-FGRS — it turns a family's case/control status and ages of onset into a continuous, GWAS-ready estimate of each person's genetic liability, and fits the variance-component model behind it.

v0.1.0.dev0 174 tests passing ~3,600 LOC · numpy + numba Python ≥3.9 GPL-3.0

The whole package lives on this picture: a latent Gaussian liability ℓ per person, a diagnosis when it crosses a personalized threshold T, and a posterior mean of the proband's genetic liability recovered from where their relatives' liabilities must lie.

01

The method lineage it implements

ltpred is a faithful, tested port of a specific line of methods — each paper adds one thing to the liability-threshold model, and ltpred implements them on one covariance engine with two interchangeable back-ends.

A latent normal liability; a disease when it exceeds a threshold set by prevalence.

Family history as a phenotype

2023ADuLT

Age-dependent threshold

The same personalized threshold as a robust, ascertainment-proof alternative to time-to-event (Cox) GWAS.

Pedersen et al., Nature Communications

Deterministic, registry-scale

A closed-form Pearson–Aitken sweep with an age-censored-control mixture — the same estimate without MCMC, at biobank scale.

03

One idea underneath it all

The estimate is the mean of the family's liability distribution, restricted to the box the observations imply — and because it's Gaussian, it factors cleanly into a genetics part and a data part.

ĝ0 = w⊤μ,   w = V−1c,   μ = E[ ℓF | ℓi ∈ (ai, bi) ]
w — BLUP weights

Selection-index weights from heritability and kinship only. Threshold-free; they do the ranking. Reduces exactly to GBLUP when liabilities are observed.

μ — truncated means

What each relative's liability must average, given status and age. This is where every threshold lives — prevalence, age of onset, sex, birth cohort, ascertainment.

A consequence the benchmarks make concrete: since the thresholds touch only μ, personalizing them (by cohort or sex) always fixes calibration — and additionally lifts ranking/power whenever cases span strata of different prevalence, because two same-onset cases from different eras hold different true liabilities that a single prevalence would collapse.

05

Where it's going

The estimation and fitting cores are in place and tested. What's next splits into closing loops that already have the machinery, deepening the model, and reaching production scale.

Close the loop

Near-term
planned
Feed fitted C / M back into prediction. fit_variance_components estimates the shared- and couple-environment components, but estimate_liability has no c2= / m2= argument yet — wiring the fitted covariance end-to-end.
shipped
A λGC / false-positive panel. bench_confounding pairs a secular prevalence trend with birth-cohort-correlated null SNPs: cohort-blind (single-K) thresholds inflate genomic control up to ~15× (worse than raw case/control) while cohort-aware LT-FH++ holds λGC ≈ 1 — the confounding side of the cohort story.
shipped
Calibration diagnostics. bench_calibration now reports the calibration slope / intercept and decile (tail) calibration alongside correlation — the estimate is a self-calibrating posterior mean under the correct model, and a wrong assumed h² tilts the scale while leaving the ranking robust.

Deepen the model

Medium-term
partly done
Relationship-specific environments. A + sibship C + couple M ship today; a maternal-lineage rearing environment and cousin environments are the next valid equivalence-class components for extended registry pedigrees.
planned
Sex- and cohort-specific covariance. Move sex and birth cohort from the threshold (where they correct calibration) into Σ — sex-specific h², a cross-sex genetic correlation rg < 1 — so they also become a ranking / power lever.
planned
Direct vs. indirect (genetic-nurture) effects. Separate a proband's own genetic effect from parental effects — an asymmetric / structural covariance extension of the current symmetric model.
planned
Competing-risk CIP helpers. Kaplan–Meier / Aalen–Johansen estimators to build the cumulative-incidence curves thresholds_from_cip consumes, straight from registry follow-up with competing mortality.

Reach scale & ecosystem

Longer-term
planned
Sparse, streamed covariance. A chunked driver for single giant pedigrees and biobank runs that can't hold every family in memory at once.
planned
End-to-end GWAS example. Real-LD HAPNEST genotypes → liability score → mixed-model GWAS, with covariate / residualization helpers.
in progress
Packaging & a docs site. A tagged PyPI release beyond 0.1.0.dev0, and MkDocs / Sphinx API docs — a lean README, the user guide (with a full function reference) and the algorithm write-up already live in docs/.
